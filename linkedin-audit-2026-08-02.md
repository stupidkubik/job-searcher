## Приоритетные улучшения

### 1. Добавить Experience — критично

В публичной структуре профиля сейчас нет раздела `Experience`. Это скрывает хронологию, масштаб Tinkoff Journal, текущую роль в Playbox и ключевые результаты. Добавьте отдельные записи как минимум для:

- Creative Developer — Playbox;
- предыдущей роли / ролей в Tinkoff Journal;
- релевантного опыта Frontend Development, если он оформлен отдельно.

В каждой записи: 3–5 буллетов, стек, один проверяемый результат. Первым буллетом Tinkoff можно вынести сокращение производственного времени longreads на 50%.

### 2. Добавить Skills и закрепить ключевые три

Сейчас видны только top skills, а самостоятельного раздела `Skills` нет. Добавьте не менее 15 навыков и закрепите: `React.js`, `TypeScript`, `JavaScript`.

Следующая группа: Next.js, Frontend Development, UI Engineering, Testing, Playwright, Vitest, CSS, Design Systems, Performance Optimization, Accessibility, Git.

### 3. Добавить Featured

Сделайте 2–4 доказательства «в один клик»: портфолио, сильный кейс Tinkoff / Playbox, GitHub или demo, один технический пост. Без Featured рекрутер не доходит до работоспособных примеров.

### 4. Уточнить headline под поиск

Текущий headline чистый, но короткий: в нём не хватает `Frontend`, `UI` и ценностного сигнала. Вариант для ролей Frontend / Software Engineer:

`Frontend Software Engineer | React, TypeScript, Next.js | UI Systems, Testing & Performance`

Если целевая роль именно Creative Developer, лучше не смешивать направления в одной формулировке без приоритета. Тогда требуется отдельное решение о главной целевой роли.

### 5. Сжать и усилить первые строки About

Текст содержательный, но первые строки можно сделать быстрее для сканирования и добавить job-title keywords. Рекомендуемая версия ниже. Она использует только факты, уже размещённые в текущем профиле.

```text
Frontend Software Engineer focused on React, TypeScript, and Next.js. I build reliable, component-driven web interfaces and improve the systems behind content production.

At Tinkoff Journal, I worked on production workflows for a high-traffic publishing platform. I developed reusable component patterns and automation scripts that reduced production time for complex longreads by 50%.

Based in Serbia and open to remote or local Frontend / Software Engineer roles.
```

### 6. Сделать публикации языково последовательными

Технические посты демонстрируют сильное современное мышление: UI architecture, CSS standards, performance. Но для международного поиска лучше публиковать на английском или в формате English first + короткая русская версия. Это согласует профиль, headline и аудиторию рекрутеров.

### 7. Настроить Open to Work точнее

Проверьте, что там перечислены не только форматы работы, но и точные должности, например `Frontend Engineer`, `Frontend Developer`, `Software Engineer`, `UI Engineer`. Не добавляйте несвязанные роли: это размывает выдачу Hirify и LinkedIn.
