# Смежные web-роли: анализ четырёх проходов Hirify — 4 октября 2026

Цель отчёта: сохранить результаты четырёх последовательных рыночных проходов и зафиксировать новую стратегию поиска работы вне узкого фокуса Frontend Developer.

Исследованные направления:

1. Web Content / CMS / Digital Production
2. Web Operations / Website Operations
3. Marketing Operations / MarTech
4. Website Support / Technical Support

Главное условие поиска остаётся неизменным: удалённая работа обязательна. Поэтому высокий skill fit сам по себе недостаточен. Вакансия должна также допускать работу из Сербии либо иметь подтверждённый Global / Europe / EMEA remote без блокирующего work authorization.

Отчёт основан на exact Hirify-карточках, сохранённых в canonical tracker, и на first-party проверках работодателей там, где удалось открыть careers/ATS listing через Browser.

Основные диапазоны:

- Web Operations: job-0542 — job-0555
- Marketing Operations / MarTech: job-0556 — job-0572
- Website / Technical Support: job-0573 — job-0588, плюс пересекающиеся job-0543 и job-0551

### Метод

Во всех проходах использовалась одна логика:

- сначала узкие title families;
- затем близкие смежные названия;
- открытие exact Hirify card;
- дедуп по source_job_id и tracker indexes;
- проверка полного описания перед решением;
- для перспективных карточек — поиск exact employer careers / ATS page через Browser;
- отдельная проверка geography и work authorization;
- фиксация каждой просмотренной exact vacancy, включая закрытые, архивные, неподходящие и дубли;
- при Hirify Too many requests проход прекращался без обхода rate limit и без подмены exact-card evidence поисковыми сниппетами.

Hirify оказался полезным для проверки существования профессий и поиска title patterns, но текущая выдача заметно загрязнена country-specific remote и гибридными вакансиями.

## 2. Главный вывод

До этих проходов профиль фактически подавался рынку как:

Junior Frontend Developer с необычным редакторским прошлым.

Результаты показывают, что это слишком узкая и невыгодная рамка.

Более точная рыночная модель:

**специалист по web / digital operations с сильным опытом контента и CMS, который дополнительно умеет работать с HTML/CSS/JavaScript, QA, интеграциями, browser debugging и автоматизацией.**

Это меняет роль технических навыков.

Старая логика:

разработка — основная профессия, CMS/content — дополнительный опыт.

Новая логика:

CMS, content production и digital operations — зрелый профессиональный фундамент; разработка, API, QA и automation — редкое техническое усиление.

Четыре исследованных рынка оказались не четырьмя случайными pivot-направлениями, а одним связным кластером:

**CMS + web production + troubleshooting + HTML/CSS/JS + QA + APIs/integrations + documentation + automation.**

- US only;

### Новый geo order

При discovery и triage приоритет:

1. Serbia remote
2. Global remote

Но во время title discovery нельзя фильтровать географию настолько рано, чтобы потерять evidence о самой профессии.

# 9. Общий skill pattern

Высокий fit возникает не там, где требуется максимальная глубина React.

Повторяются комбинации:

- CMS + HTML/CSS;
- publishing + QA;
- JavaScript troubleshooting + analytics;
- content + Figma + AI;
- APIs/webhooks + CRM;
- DevTools + documentation;
- accessibility + SEO + release QA;
- WordPress + DNS/SSL + integrations;
- SQL/logs + web application troubleshooting.

Главная рыночная сила профиля — гибридность.

Это редкий набор для purely junior developer, но нормальный и полезный набор для digital operations.

# 10. Seniority должна стать lane-specific

Один общий уровень Junior Frontend больше не описывает весь рынок.

### Frontend / product development

Junior / Junior+ остаётся адекватным.

### Content / CMS / Digital Production

Здесь коммерческий production опыт существенно глубже.

Можно смотреть:

- ungraded;
- Junior/Middle;
- Middle;
- иногда Senior, если seniority означает editorial/production expertise, а не people management.

### Web Operations / Website Support

Опыт CMS, QA, web production и troubleshooting хорошо переносится.

Реалистичны:

- Junior+;
- Associate;
- Middle;
- некоторые ungraded specialist roles.

### MarTech

Реалистичны technical specialist / automation roles.

Пока не реалистичны manager / RevOps jobs, требующие многолетнего ownership marketing systems.

# 18. Итоговая стратегия

Четыре Hirify-прохода подтвердили реальную возможность сместить поиск с чистой разработки без обнуления предыдущего опыта.

Профиль недооценивается, когда описывается главным образом как Junior Frontend Developer.

Более точное позиционирование:

**опытный специалист по content/CMS/web production, который способен не только выпускать контент, но и диагностировать, автоматизировать и интегрировать цифровые системы вокруг него.**

Лучший immediate profession fit:

**Web Operations / Digital Experience.**

Лучшее использование накопленного опыта:

**Content / CMS / Digital Production.**

Самое широкое новое technical-adjacent расширение:

**Website / Technical / Product Support.**

Самый перспективный specialist pivot после небольшого дообучения:

**Marketing Operations / MarTech.**

Frontend не нужно бросать. Его роль меняется: это один из каналов поиска и технический рычаг внутри других профессий, а не фильтр, отсекающий весь остальной рынок.
