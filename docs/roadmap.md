# Roadmap

Отложенные этапы автоматизации. Не начинать SQLite, dashboard, GitHub Issues intake
или внешние API до стабилизации write-path CSV и накопления достаточных данных.

## Stage 1 — базовый журнал

- **Цель:** единый CSV + Markdown, актуальный профиль, раздельные CV и CI.
- **Условие старта:** выполнено в текущей v1.
- **Входы / выходы:** ручной поиск → валидированная строка `jobs.csv` и, при
  необходимости, карточка в `applications/`.
- **Риск:** ручная запись в обход CLI приводит к расхождению схемы.
- **Готово, когда:** `validate` и unit-тесты проходят, а все новые вакансии имеют
  записи.

## Stage 2 — регулярные отчёты

- **Цель:** еженедельно фиксировать воронку, источники, response rate и overdue
  действия.
- **Условие старта:** есть минимум несколько реальных заявок и обновлённые даты.
- **Входы / выходы:** `jobs.csv` → `reports/weekly/YYYY-Www.md`.
- **Риск:** автоматический отчёт без актуальных статусов создаёт ложную картину.
- **Готово, когда:** отчёт генерируется командой `jobs.py report` и используется
  в еженедельном обзоре.

## Stage 3 — улучшение дедупликации

- **Цель:** ускорить поиск повторных публикаций без автоматических потерь данных.
- **Условие старта:** появляются регулярные совпадения между несколькими boards.
- **Входы / выходы:** `original_url`, нормализованные company + role → список
  кандидатов на ручное решение.
- **Риск:** fuzzy-совпадение ошибочно склеит разные роли одной компании.
- **Готово, когда:** инструменты лишь сигнализируют о кандидате, а `Duplicate`
  всегда подтверждается человеком или агентом с источником.

## Stage 4 — безопасный intake

- **Цель:** принимать вакансии из forms, email или GitHub Issues без обхода схемы.
- **Условие старта:** ручной write-path стабилен и регулярно используется.
- **Входы / выходы:** внешний сигнал → черновик / pull request → `jobs.py validate`.
- **Риск:** внешняя интеграция напрямую испортит CSV или создаст дубли.
- **Готово, когда:** ни один внешний источник не пишет в `jobs.csv` напрямую.

## Stage 5 — UI и более сложное хранилище

- **Цель:** dashboard или SQLite только при реальной необходимости нескольких
  представлений, связей или одновременных writers.
- **Условие старта:** CSV-история стала неудобной для ответов на реальные вопросы.
- **Входы / выходы:** валидированные CSV-данные → UI / миграция с audit trail.
- **Риск:** преждевременная сложность и потеря прозрачных Git-диффов.
- **Готово, когда:** новая система сохраняет все инварианты v1 и имеет безопасную,
  обратимую миграцию.
